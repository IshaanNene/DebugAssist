# Contributing

DebugAssist is a uv workspace of Python packages plus a Next.js dashboard and two browser SDKs. `CLAUDE.md` holds
the non-negotiables; this page is how to change things without breaking them.

## Set up and check

```bash
make bootstrap   # first time: Python dependencies and the git hooks
make doctor      # what this machine has and lacks (changes nothing)
make check       # ruff, pyright strict, pytest — what CI runs
make coverage    # the same tests with the coverage floors CI enforces
make api-types   # after changing an API response model: regenerate the dashboard's types, commit both files
```

Use `make sync` instead of a bare `uv sync` on macOS (it restores the editable-install path hook). Unit tests never
see your credentials: the root `conftest.py` hides every setting's environment variable and `.env`, and points the
audit log at a per-test file. Tests that call real APIs are marked `@pytest.mark.live` and run only with
`DA_LIVE_TESTS=1`.

The dashboard's API types (`apps/dashboard/src/lib/api-schema.ts`) are generated from the API's OpenAPI schema
(`apps/dashboard/openapi.json`) — edit the Pydantic models in `packages/api/src/debugassist/api/models.py`, never the
generated file. A test fails when the committed schema differs from the API, and CI fails when the generated types
differ from the schema.

## Layout

| Package | What it holds |
|---|---|
| `core` | settings and modes, the write policy and audit log, guards, redaction, host git, tracing, run context |
| `decisions` | the decision engine, Clef / LLM / rules backends, templates, the ledger |
| `integrations` | GitHub, the GitHub App, Jira, chat, the sandbox |
| `llm` | the agent runner (live, cassette replay, scripted), workspace tools, middleware |
| `mcp_servers` | the eleven MCP servers agents use |
| `pipeline` | the fixed LangGraph plan: `nodes/` (one module per node), `graph.py`, `state.py`, release checks, the App poller |
| `api` | the dashboard's API and the webhook |
| `harness` | agent types, skills, runtime images, the queue worker |
| `evals` | scoring, replays, reports, the red-team catalogue |
| `scenarios`, `simulator` | the bug catalog's injection and the traffic that discovers it |

A new package is `packages/<name>/pyproject.toml` (hatchling, `packages = ["src/debugassist"]`), added to the root
`[tool.uv.sources]` and `dependencies`. `debugassist` is an implicit namespace package: no `src/debugassist/__init__.py`.

## Common changes

**An external write** (a comment, a ticket, a push). Add the action to `configs/policies/writes.yaml` and make the
call through `deps.gate.gated(action, lambda: …, run_id=…, detail=…)`. `test_gated_writes.py` fails on a write
client call in `pipeline/` without a gate; a new client method name goes in its `WRITES`.

**Touching a run's worktree.** Use `sb.workspace` (or `Workspace(path)`) for git, reads, writes and walks: the worktree
is written by the agent, and the workspace's guards refuse `..`, symlinks out, `.git` and secret files.
`test_workspace_only.py` fails on a `hostgit` call, a `worktree / …` join or a `walk_files` in `pipeline/`.

**A pipeline node or edge.** Nodes live in `pipeline/nodes/`, one module each (shared helpers in `nodes/common.py` and
`nodes/testing.py`), are exported from the package by name, and are registered in `state.NODE_KIND`; edges in
`graph.build_graph`. `test_graph_edges.py` reads the edges from the built graph: add a row for every way out of a
new edge, or the test fails.

**Host access to a run's worktree.** Never `subprocess.run(["git", …], cwd=worktree)`: use `core.hostgit.run`,
which refuses a `.git` the agent planted. Walk files with `guards.walk_files`, read them through `guards.confine`.

**A decision.** A template in `packages/decisions/templates/` and its mock answer in
`pipeline/deps.MOCK_DECISIONS`. The deterministic overrides at the ship gate stay deterministic: a decision may
make the outcome more cautious, never less.

**An MCP tool.** In the server's module, returning `with_evidence(…)` so its result has an evidence id and is
redacted; writes go through `common.gated_write`.

**A number in the docs.** Results only from `evals/reports/` generated by a repo command. A limit next to its
constant is written `` `NAME` = value ``; `test_doc_constants.py` compares it with the code.

## Style

Python 3.13, ruff (line length 110), pyright strict at 0 errors. Pydantic models at every boundary; persisted
records typed where they can be — `test_typing_ratchet.py` lets `dict[str, Any]` in `pipeline/` only fall.
Comments say why, not what. Conventional commits; one phase at a time, with `docs/PROGRESS.md` updated at its end.
Target repositories are submodules with their own history: see `CLAUDE.md` before committing there.
