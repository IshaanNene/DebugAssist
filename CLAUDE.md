# DebugAssist — notes for Claude Code sessions

Read `docs/SPEC.md` (requirements, verbatim) and `docs/PLAN.md` (§0 amendments override the spec) at the start of every phase. Progress lives in `docs/PROGRESS.md`; design decisions in `docs/adr/`.

## Non-negotiables
- **LLM = OpenRouter `openai/gpt-oss-120b`** (OpenAI-compatible API). Never add Anthropic/Claude SDK calls (PLAN A1).
- **Clef decides, the LLM reasons/writes code, deterministic code acts.** Clef output never triggers a write directly — it goes through a policy YAML and the write-policy gate.
- **The plan is fixed in code.** LLMs never choose the next graph node.
- **Mock mode everywhere.** Every external integration has a mock; CI has no secrets. Mode resolution: `debugassist.core.settings.Settings.mode()`.
- **Never fabricate results.** Numbers in README/RESUME come only from `evals/reports/` generated by a repo command, from live runs.
- **Ground truth never reaches the agent.** Nothing under `groundtruth/` may be mounted into a sandbox or referenced from target repos.
- **Safety.** Agents act only inside a sandbox container + git worktree. Pushes only to `debugassist/*` branches of `IshaanNene/miniride-client` / `IshaanNene/miniride-services`. Write actions are policy-gated, audited, dry-run by default.
- **Cost.** Ask before any run estimated above $5. OpenRouter key limit is $50.
- No affiliation with Uber or Cloudflare. Our names: BugDrop ≈ Wisdom, Vitals ≈ Healthline.

## Conventions
- Python 3.13, uv workspace (`packages/*`), shared namespace `debugassist.*` (implicit namespace package — no `src/debugassist/__init__.py`).
- New package: `packages/<name>/pyproject.toml` (hatchling, `packages = ["src/debugassist"]`) + add it to root `[tool.uv.sources]` and `dependencies`.
- Pydantic v2 models for every boundary. Pyright strict must stay at 0 errors. Ruff line length 110.
- Tests next to each package in `packages/<name>/tests/`. Tests that hit real APIs are marked `@pytest.mark.live` and skipped unless `DA_LIVE_TESTS=1`.
- Verify third-party APIs against current docs before coding; record live responses as fixtures under `tests/fixtures/`.
- Conventional commits. One phase at a time; update `docs/PROGRESS.md` at the end of each.
